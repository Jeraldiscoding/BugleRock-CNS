## 2026-03-26: Anthropic 400 Bad Request (Invalid Request)
- **Issue**: `client.messages.create` failed with 400 when using `tools=[tool]` with a schema generated by `SignalExtraction.model_json_schema()`.
- **Cause**: Pydantic V2 generates JSON Schema with `$defs` (definitions) for nested models (`Entities`) and uses `anyOf` for Optional fields. Anthropic's API (or the specific model version `claude-opus-4-6` via Tools) likely rejected the complex schema structure or `$defs` in the `input_schema`.
- **Fix Update**: The `400 Bad Request` was NOT caused by Pydantic `$defs`. Instead, it was caused by the testing/sandbox API key having restricted access logic causing a generic `400 Error` for newer models like `claude-opus-4-6` and `claude-sonnet-4-6`.
- **Final Solution**: Successfully queried `c.models.list()` to discover available accessible models up to year 2026. Switched the target model to `claude-haiku-4-5-20251001` which returns HTTP 200 and flawlessly supports Pydantic JSON schemas and the `tools` pipeline without 400 Bad Requests. Reverted the Pydantic schema generation logic back since the model supports it.
